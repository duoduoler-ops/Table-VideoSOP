# 本期复盘

> 整期交付后或用户要求时复盘一次，把本期真实反馈变成下一期能直接用的东西：正面样例、少而准的规则修改、可删减项。报告放本期 `06_审片与QA/`；系列规则只改用户选定的项。配套提示词见 `prompts/09_复盘.md`。

## 制作中怎么记

- 用户对画面、节奏和流程的反馈，**原话**记在 QA 状态表对应对象的证据里（写“用户原话：……”），不改写成规则语言。
- 本期问题先改本期任务书或本期说明，让本期继续；系列规则到复盘时统一升级。阻塞本期、必须立即改系列规则时，记下生效时间，复盘时核对效果。

## 1. 满意的画面（正面样例）

| 片段与准确路径／时间段 | 截图或总览图 | 观众角度为什么好 | 可量特征 | 适用范围 |
| --- | --- | --- | --- | --- |
|  |  |  | 主体尺度、字号、静止占比与最长静止、镜头方式 |  |

满意片段登记到系列范例或公共资产索引，作为今后的对标片。本节不能省略；没有就写“本期无”并说明原因。

## 2. 返工记录

| 对象 | 用户原话 | 问题层级 | 返了几轮、最后怎么解决 | 规则没写，还是写了没执行 |
| --- | --- | --- | --- | --- |
|  |  | 内容／画面尺度／节奏／运动手感／流程／事实 |  |  |

- 写了没执行：改入口、任务书或模板里的触发位置，不新增条文。
- 规则没写：先看能否改写现有条目；写入时保留正反两面（问题是什么、做成什么样才算好），不只留一句禁止，也不能丢掉用户原话里的任何一半。

## 3. 可删减

本期没用上、造成负担或与别处重复的规则、检查和证据文件。每提议新增一条，至少同时检查一处能删减或合并。

## 4. 几个数字

各段过审前返工轮次、第一版就通过的段数／总段数、耗时或用量最大的环节。下一期按同一口径对比，判断改动是否有效。

## 5. 升级决定（交用户选）

| 建议 | 改哪个文件 | 通用方法／系列偏好／本期特例 | 用户决定 |
| --- | --- | --- | --- |

通用方法进经验正文，系列偏好进 DESIGN 或系列规则，本期特例留在本期。用户选定后再改，并核对受影响的引用和任务入口。

## 边界

- 只依据真实文件、QA、接入说明和用户原话；未验证的想法单列候选，不写成经验。
- 不把单期帧数、构图或个人偏好升级为跨项目默认。
