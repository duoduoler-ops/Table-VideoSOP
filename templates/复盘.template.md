# 本期复盘

> 整期交付后或用户要求时复盘一次，把本期真实反馈变成下一期能直接用的东西：正面样例、少而准的规则修改、可删减项。报告放本期 `06_审片与QA/`；系列规则只改用户选定的项。配套提示词见 `prompts/09_复盘.md`。

## 制作中怎么记

- 用户看片意见在制作中按**原话**记入 QA 状态表，做法见 `docs/04_验收与返修.md`“返修只重查受影响内容”；复盘直接引用，不改写成规则语言。
- 本期问题先改本期任务书或本期说明，让本期继续；系列规则到复盘时统一升级。阻塞本期、必须立即改系列规则时，记下生效时间，复盘时核对效果。

## 2. 返工记录

| 对象与证据 | 用户原话 | 问题层级 | 返工与结果 | 返工类别 | 导致问题的机制与证据 |
| --- | --- | --- | --- | --- | --- |
|  |  | 内容／尺度／节奏／运动／流程／事实 |  | 规则没写／写了没执行／规则导向错误／判断失误 |  |

作者按实际证据分四类，可有多个原因但须分别解释：规则没写先辨新模块还是旧边界缺失；写了没执行追查入口、交接、执行或检查为何失效；规则导向错误指出遵守哪句仍造成坏结果并修原条文；判断失误记录当时依据与漏查对象，修核验动作，不凭一次失误泛加规则。

## 3. 重复与含糊项

列重复、含糊或失效条文及影响。修补就替换原条文，同一件事只在一处维护正文，其他入口短链引用；新增模块可增加必要文字，不设字数上限，不强凑删减项。

## 4. 几个数字

各段返工轮次、首版通过段数／总段数、耗时或用量最大的环节；下一期用同一口径比较效果。
