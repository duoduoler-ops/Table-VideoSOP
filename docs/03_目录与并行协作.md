# 目录与并行协作

## 基础目录

```text
系列根目录/
  AGENTS.md
  DESIGN.md                         # 静态和动态测试确认后建立
  docs/ experience/ prompts/ templates/ examples/
  00_系列测试/                      # 自己的静态、动态候选与确认记录
  01_公共资产/                      # 自己的角色、字体、参考、复用组件
  第01期_主题/
    00_本期控制/                    # 本期说明、制作大段表、分段开工指令
    01_稿件/                        # 原稿、可选审稿建议、确认定稿
    02_配音/                        # 原始录音、采用配音、派生字幕
    03_视觉设计/                    # 正文镜头剧本、各段设计与跨段衔接依据
    04_素材/                        # 实际素材、生成提示词、来源
    05_制作工程/                    # main、分段源码、renders、_work
    06_审片与QA/                    # 唯一 QA 表、局部证据
    07_交付/                        # 成片、字幕、clean母版、复现说明
    08_发布素材/                    # 封面、标题、简介与检查记录
    90_历史归档/                    # 被替代版本
```

按实际阶段补目录，不创建空音频、空确认记录或虚构状态。`main/` 登记所选工具实际入口；Remotion 可以使用 `remotion-main/`，以本期表中的真实路径为准。

先定位已有单期目录。尚无单期且未给期名时，按内容取临时期名，例如 `本期_资料归档/`；纯审稿只需其中的 `01_稿件/`，单段方案只补对应设计或素材目录。不能因缺期号就将系列根视为本期，也不要求补齐整套目录。

## 确认大段表后自动准备

本包默认由用户开启新对话并行；用户选串行则跳过并行包。用户确认表版本、划段、路线、分工后，总控同次完成以下工作：

1. 核对当前表版本、稿件、配音和允许阶段。配音未确认时只派与时基无关的设计或素材准备。
2. 检查目标路径、已有文件与目录链接，只补缺项，保留现有成果。
3. 按选定大段创建下列专属目录，使用[任务书模板](../templates/开工任务.template.md)。
4. 把每段的实际入口写入 `00_本期控制/分段开工指令.md`，替换所有占位符。
5. 检查输入存在、写入范围互不重叠、章节转场归属明确；在聊天交付每段可开始的阶段与阻塞。
6. 按[镜头剧本模板](../templates/镜头剧本.template.md)一次写完 `03_视觉设计/正文镜头剧本.md`（单独打磨的段落可按系列约定除外），交用户审一次。任务书写明本段小节与对标片；剧本还没有本段小节时，写明允许本段只补写自己一节并先交用户确认。正式批量动画按本批范围放行，开始前由总控核跨段衔接；用于解决新类型或未解高返工风险的设计期局部预演按[验收规则](04_验收与返修.md#完整过程预演与精修)提前，不借预演扩大正式制作范围。

```text
03_视觉设计/D01_段名/
04_素材/分段/D01_段名/
05_制作工程/分段/D01_段名/
  开工任务.md
  src/
  scripts/
  _work/
06_审片与QA/分段/D01_段名/
  预览/
  接入说明.md
```

D02 等使用各自同级目录。主工程、公共资产与总控文件不落入任何分段专属写入范围。总控可以创建这些目录，但分段任务不因此获得总控文件写权限。

## 可复制指令

总控为每段生成下列三行，全部填入使用者电脑上的真实绝对路径；公开模板不预置作者路径。

```text
在【系列根绝对路径】工作，负责【期名／大段ID与名称】。
读取【系列AGENTS绝对路径】和【本段开工任务绝对路径】，核对当前依据，按任务书允许阶段和写入范围直接开始。
将成果路径、验证和未解决项写到任务书指定的接入说明，完成本段后停止。
```

每个新对话仍从系列根目录开启并显式读取任务书。资料准备完成后由用户开启对话，不自动派子 Agent、启动高负载渲染或安装依赖。

## 分段与总控职责

| 对象 | 分段任务 | 总控 |
| --- | --- | --- |
| 本段设计、源码、参数、私有预览 | 在专属目录内读写 | 核对与接入 |
| 制作大段表、QA 状态表 | 只读；接入说明提出更新建议 | 记录采用、进度与检查结论 |
| 共享素材、组件、依赖与正式总装 | 只读；提出所需接口 | 实施公共改动，避免冲突 |
| 渲染与交付 | 轻预览；重渲染交总控协调 | 资源调度、正式成片、最终 QA |

任务书绑定表版本。表改变后，总控只更新受影响任务，并提醒暂停依赖旧版本的工作；与改动无关的工作继续。任务书、接入说明是执行依据与局部证据，不建立第二套中央状态。

只有真实依赖冲突或风险试验需要隔离时才另建临时工程，记录原因、输入输出、回收方式和负责人。正式交付要能从登记的总装入口复现。

## 分批放行

总控先准备完整任务书，按允许阶段、输入依赖和不重叠写入范围只启动第一批；资料准备完成不表示后批已经放行。首批实际结果交用户看过、落实反馈并核缺陷闭合后，再放行后批。使用当前宿主已授权的协作方式；没有相应工具或消息授权时提供可复制开工指令，不自动创建工人或联系外部渠道。用户已有明确分批安排直接承接。

正例：首批暴露共性问题，先修任务书再启动后批；反例：口头说先做首批却同时发出全部任务。执行者交实际产物、用户原话与未验证项，总控复审版本、接点和缺陷并写回唯一中央记录。

## 环节任务书

在既有任务书顶部按当前环节填采用输入与时基、允许动作、本批范围、专属路径、输出和责任人；转阶段更新同一任务书，不补建五套状态。跨环节输入在最早会改变它的步骤确定，后续引用同一记录。

| 环节 | 执行者与总控检查职责 |
| --- | --- |
| 粗剪 | 执行者核实际人声边界、保护章间留白并记录时基；总控核当前配音和未听校处，用户听确认。方法见[声音与留白](06_音效与配乐_可选.md#配音粗剪与章间留白) |
| 设计 | 执行者按已审剧本取够用的关键状态、判断空间适配并处理未解风险；总控核画面增量与跨段安排 |
| 分段动态 | 执行者仅做本批允许段，交覆盖采用配音的完整预览并核原尺寸缺陷；总控核缺陷闭合、测量缺口与 1× 实际审看范围 |
| 总装 | 执行者接当前采用版本、同源字幕和已认可声音，核真实接点；总控核版本与接入，再组织锁画和 Final QA |
| 总控 | 核权威输入，最早安排跨环节要求，批量动态前核跨段，分批放行并回收复审 |

任何环节新增、修改或审核画面均先读项目 DESIGN；准备生成提示词时读生成经验，沿用本包用户手动提交边界；制作字幕时读[字幕经验](../experience/字幕与封面.md#字幕)。检查节点和盲区见[工具说明](../tools/README.md#固定节点与人工复核)。正例：粗剪时就保护留白；反例：总装才发现已剪掉章间时间。派工前总控沿本卡核输入与允许阶段，收回后核实际结果。

## 公共资产

媒体登记来源与用途；代码组件在再次复用前去掉本期文案、路径和时基，将差异做成参数并说明验证范围。候选、可复用实现与历史范例分开标记，范例不等于即插即用组件。更新公共资产不自动改写已完成单期。

完整过程范例登记适用前提、实际确认片及区间、源码、主动作步骤、镜头目的、不可丢失的对象关系和验证范围；复用时重排本段构图与时间，不能只摘局部特效。抽象结构可参考[完整过程参考](../experience/镜头推进与转场.md#完整过程参考)，没有实际证据的结构只作候选，不冒充成熟组件。
