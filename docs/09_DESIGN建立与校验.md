# DESIGN 的建立与校验

本包融合 [google-labs-code/design.md](https://github.com/google-labs-code/design.md) 的格式和视频制作需要。该项目提供设计身份的表达格式；[awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 提供写法样例。两者不能代替自己的静态与动态测试，也不自动带来你本地已有的运动规则。

## 三部分如何合并

1. 采用上游格式的基础字段：颜色、字体、圆角、间距和组件引用；正文解释用途。字段定义按[上游规范](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md)核对。
2. 用本包 `x-video` 扩展保存画布、呈现层、包装、图形语义、动作曲线、校准参数和确认证据。它是本包扩展，不宣称上游 CLI 会验证这些视频语义。
3. 借鉴本地成熟规则的精度：可执行参数、组件比例、动作因果与例外范围都保留；个人颜色、角色、帧数和风格换成使用者自己的测试值。

## 从测试到正式规范

按[设计提示词](../prompts/02_建立DESIGN.md)比较静态样本，再在同一视觉下做运动测试。用[详细模板](../templates/DESIGN.template.md)填候选。每个当前会用到的 token 都须有具体值；明确不使用的可选结构说明不适用，不能让模板空值进入实现。

先由 Agent 从确认样本填参数，不让用户逐格设计 JSON。用户只需判断真实画面与运动，并确认采用范围。完整机器参数服务复用，不要求作者手工填完所有字段。

测试内容要覆盖本系列实际需要的质量。例如资料流转应展示同一对象处理前后的变化、接收反馈和结果阅读。没有角色不等于可以省去图形细节、层级和对象关系。某项运动不适用时可以省略，但只验证了直线位移的示例不能证明复杂交互效果。

JSON front matter 是本包选用的 YAML 子集。通用 token 使用 `fontSize`、`fontFamily` 等上游字段名；迁移已有规范时，将自定义字段映射到对应标准字段，再检查消费者。字体、间距、圆角采用带单位字符串；画布坐标、帧数和比例按 `x-video` 字段含义使用数值。

正文尽量引用参数名而不是复制数值。派生给代码的 JSON 从同一 DESIGN 解析生成，不人工维护第二份设计参数。

## 验证分三层

- 结构：front matter 可解析，引用存在，颜色与单位有效，没有未填写的必需项，正文和参数职责一致。
- 实现：实际卡片、字幕、路径与组件取用了这些值；缺字体后的布局也经过检查。
- 视觉：真实静态图和动态样片能证明构图、语义、动作因果、阅读与衔接。通过结构校验不能代替后两层。

可在批准安装后选用上游 CLI 做额外结构检查；本包不默认安装它，也不把自带检查称为官方 lint。规范仍在演进，接入时核对版本。视频扩展由本包工具和实际样片另查。

见[详细填写示例](../examples/03_DESIGN填写示例.md)。该例独立展示参数和正文，不附带工程或已通过审阅的视觉样本。
