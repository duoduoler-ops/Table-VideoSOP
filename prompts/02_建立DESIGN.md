# 建立自己的 DESIGN

三段提示词分阶段使用，不一次性跳过静态与动态确认。填写的路径以系列根目录为基准；实际采用版本由 Agent 核对。

## 第一步：静态测试

```text
读取 AGENTS.md 和 templates/DESIGN.template.md，准备本系列静态设计测试。
内容类型与受众：[填写]
想要的观感：[填写]
不喜欢的观感：[填写]
画幅与观看场景：[填写]
参考图及职责：[路径；分别说明画风、构图、身份或道具]
角色：[角色说明路径／不使用]

先区分已经明确的偏好和待比较项。用同一段中性内容制作少量有实质区别的真实画面方案，展示背景、字体、层级、图形和角色的配合，保留可编辑参数。
能够程序绘制或用已提供素材完成的，直接按当前授权制作；需要生成式图片时，准备完整提示词和上传说明交给我手动生成。
干净设计图与说明分开，不以占位框代替真实外观。候选保存到 00_系列测试/静态/，告诉我应重点比较什么。
这一步不把候选写成已确认的 DESIGN。
```

## 第二步：动态测试

静态方案已确认后使用；还需要动效环境时先完成环境准备。

```text
静态方案采用：[准确路径／版本与确认范围]。
请读取 AGENTS.md、experience/视觉叙事与连续MG.md 和 experience/镜头推进与转场.md，用上述视觉方案做动态测试。
动态偏好与参考：[填写；没有则依据静态方向提出少量可比较方案]

测试需要覆盖形态变换、对象交互和结果停稳；存在附属对象时再加入跟随或次要动作。按镜头方法结合本段内容、场景与情绪选择观察方式，写明作用并用实际播放验证；不要求每项技法都做一遍。动作要说明因果，不用持续漂浮填空。
保留源码、参数和实际预览，保存到 00_系列测试/动态/。说明每个测试解决什么判断，检查过程与落定状态，不只给静帧。
结果先作为候选，等我确认具体视觉与运动方面后再整理规范。
```

## 第三步：写入规范

```text
我确认以下测试：[静态文件、动态文件、各自确认的方面]。
请按 templates/DESIGN.template.md 整理根目录 DESIGN.md，记录真实样本、版本、确认范围、视觉参数和运动规则。
把系列固定项、本期可调项与单段例外分开；测试没有验证的内容标待定，不补成默认值。角色使用 templates/角色说明.template.md 的字段，没用角色就注明。
如已存在 DESIGN，先保留原版，只修改这次确认覆盖的内容；检查它与 AGENTS 和制作 SOP 的职责是否冲突。
交付规范路径、采用依据和仍需测试的内容。
```

成功标志：规范能定位真实静态与动态样本，且没有把测试候选或单段参数扩大为系列默认。

## 第三步的精度要求

写入规范时同时应用下面的补充指令：

```text
读取 docs/09_DESIGN建立与校验.md，按详细模板生成结构化参数和正文。
从已经确认的真实样本提取具体颜色角色、六级字体、间距阶梯、圆角、边框阴影、组件比例与状态；分开 MG、真实录屏、生成场景和外部包装的适用范围。
记录出现、预备、传递、落位四类运动曲线及需要被看清的过程曲线、已验证校准样片、fps、阶段帧数、位移、角度、形变与跟随延迟及其适用范围；没有证据的参数不虚构。
检查适用的动画原则、固定项、变量、例外和确认依据。上游基础字段使用标准名称，视频参数放 x-video；不要用一句“自然流畅”替代这些约束。
先做结构与引用检查，再核对实际实现和视觉证据；区分已经通过与仍未验证的部分。对用户只总结实际采用项和待决定项，不要求逐行审参数。
```
