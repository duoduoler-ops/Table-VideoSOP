# Table Video

以用户提供的文稿与实际配音为制作依据，把当前视频任务推进到可检查的下一步：先接收材料，再按阶段读取正文、产出候选、记录真实确认，保留可恢复状态。本 Skill 不承担口播稿创作，可按需审稿提建议；后续“文字镜头剧本”由总控编写，描述已采用口播对应的观看过程，不改口播内容。默认不代生成 TTS 音频，缺配音时引导用户使用外部 TTS 或自己录音后回传。

规则以实际返回的正文为准；长文按章节读取，返回被截断就补读缺的章节，发出调用不算已读。同一任务已读且未变不重读，不另建阅读回执。

## 当前可用范围

此包为 P0 公开试用版：提供流程、状态、动态定位工具，以及可编辑的完整 MG 源码示例、调用现有 Remotion 环境的适配器及 SVG／sharp 帧输出入口。包内不含运行依赖、浏览器、TTS 或生成服务；不自动安装或下载运行依赖，也不自动提交生成任务；已授权查找参考时，按参考流程保存实际图片到用户项目。示例的局部改善证据不等于通用视觉预设、宿主自动触发成功或首发达标；工具测试不代替实际成片验收。

## 先识别任务

带分段任务书进入的对话先按[分段协作](references/sop/03_目录与并行协作.md)识别角色：只核对本段输入和允许阶段，不重走整期入口、不初始化或写中央 state。其余正式项目由当前对话担任总控。

1. 读取用户当前请求和已给材料。只审稿、写提示词、做单段文字方案或改一处文字时，进入对应参考，直接交结果；不初始化整期、state 或 QA。
2. 正式项目先定位用户项目目录。Skill 包保存指令、模板与示例代码，产物写用户项目。已有 `00_本期控制/state.json` 时先按[状态契约](references/state-contract.md)执行 status／next，核对实际文件摘要与待审事项。
3. 没有 state 时先识别是否已有旧项目控制文件；旧模式迁移走候选和明确启用，不覆盖原表。全新整期才运行 init-project。已明确的目标、画幅、声音、画面形式和风格不重问。
4. 首次整期按[首次引导](references/intake.md#首次引导)先接收本轮文稿；已提供就直接读取，不重复索要。已有配音一并核对，缺配音不阻塞读稿。目标与受众等只在材料不足且影响下一步时自然补问，不固定发开场问卷。用户明确从头开始时，以本轮提供的材料与决定为依据，不从旧项目、历史测试或作者示例预填选择。推荐不等于采用；已明确的选择直接承接，已有授权范围内继续独立工作。
5. 首次进入画面规划前执行[画面路线核对](references/intake.md#进入画面规划前核对路线)：未选先问，已选先回显；用户要求回到选型时重新询问，不拿旧方案代替本轮选择。找参考先按[参考筛选与可实现性](references/style-and-motion.md#参考筛选与可实现性)核对已选路线和当前制作能力；纯 MG 须找 MG 参考，“再找几张”不表示改换路线。路线明确后再做对应风格、分段与镜头方案。
6. 涉及 IP／角色时，先按[角色首次入口](references/intake.md#ip-与角色首次入口)核对身份素材来源和采用范围：缺图引导提供，已有候选说明来源并确认，已明确采用不重问，未定形象不凭名字选图。身份明确后，再于代表静帧制作前及新增表演需求时按[角色表演与素材充分性](references/style-and-motion.md#角色表演与素材充分性)核对叙事作用与实际素材缺口；已有授权直接承接，只暂停依赖缺失素材的部分。
7. 首次建立或改变视觉体系，先走[参考入口与转场](references/style-and-motion.md#参考入口与转场)：已给参考直接查看，来源未定先引导用户提供或由 Agent 查找；参考方向选定后才做本片代表静态。访问失败留在参考环节，不能自行转为自绘试样；用户明确选择自绘探索时才走该分支。静态确认后写 DESIGN，直接进入正式制作分段；运动使用[有来源的职责候选](references/style-and-motion.md#默认动作设计基线)起步，不安排独立参数选档。新对象演化／镜头关系缺少适用过程证据，或存在未解高返工风险时，按[测试与复用](references/style-and-motion.md#测试与复用)在设计阶段做局部过程预演；普通同类在首版完整预览核实适配。已有适用确认直接复用；静态确认不放行全片设计，独立静态交付不强制进入动画流程。
8. MG 的静态测试须由可编辑、可独立控制的实际部件绘制并输出，后续动态沿用这些部件；不能用 AI 生成的整张场景图代替，再承诺将来分层。参考图、已确认角色素材和实际制作源的职责，按[静态样本与可动部件](references/style-and-motion.md#静态样本与可动部件)区分。

任何环节新增、修改或审核画面先读项目 DESIGN；准备生成提示词时读生成经验；字幕制作读字幕经验。当前任务书按[环节职责](references/sop/03_目录与并行协作.md#环节任务书)填输入和本批范围，准备不等于放行。

## 默认效果底线

画面须提供配音之外可辨认的依据、关系或情绪变化。按[画面推导](references/planning.md#从理解目标推导画面)确定观众何时获得什么依据、哪个部件因而改变，再安排取景和时间；静态、动态和检查沿用同一实际状态源。新 MG 默认从[共用制作起点](assets/motion/production-core/README.md)接入内容、部件、XYZ 相机与时间；已有工程按[源码迁移](references/complete-motion.md)保留有效关系。示例题材、秒数和检查结果不继承为本段结论。

进出场、替换及例外范围只认[默认动作语言](references/experience/视觉叙事与连续MG.md#默认进出场与替换)；普通位移／缩放须有可辨的速度变化，真实进度按数据含义处理，用户明确约束优先。必要阅读与固定取景可以保留，主过程不能由装饰微动代替。

首版完整预览就核对[承诺与实际画面](references/production.md#剧本承诺落到实际画面)，交审执行[动态检查](references/motion-check-method.md)及项目 DESIGN 的运动门禁，静止硬门禁失败与已知视觉缺陷先修。工具结果只证明其覆盖的约束；语义、部件表现、阅读与 1× 观感仍按实际输出分别判断。

## 按阶段读取

进入画面设计（含 S03 代表静态）、MG 制作或效果返修前，必读[镜头推进](references/experience/镜头推进与转场.md#段落吸引力与镜头推进)，涉及 MG 同时读[连续 MG](references/experience/视觉叙事与连续MG.md)，按下表进入当前阶段。已读未变不重复；纯审稿、配音剪辑、文件整理不触发。

| 任务 | 必读入口 | 产物与边界 |
| --- | --- | --- |
| S01—S02 开始、稿件、配音、对齐 | [输入](references/intake.md) | 简报、输入核对、真实时基；没有词点依据不猜精确时间 |
| S03 风格与运动 | [风格与动态](references/style-and-motion.md) | 按路线筛参考、确认代表静态、记录 DESIGN；运动依经验设定，实际片段再验 |
| S04—S06 分段、镜头、设计图 | [规划](references/planning.md) | 已确认变化的状态证据、必要局部预演与跨段核对 |
| S07—S08 样片、素材、接入 | [制作与素材](references/production.md)、[默认动作设计基线](references/style-and-motion.md#默认动作设计基线)、[默认节奏](references/style-and-motion.md#默认节奏与按需对比) | 新风险先样片、成熟类型复用、完整手动任务包 |
| S09—S10 审片、返修、交付 | [审查与返修](references/review-and-repair.md) | 实际最终文件检查、明确未验证、局部失效与交付 |
| 状态写入、恢复或旧项目迁移 | [状态契约](references/state-contract.md) | 唯一采用来源、版本确认、QA 结构与恢复 |

新建或实质改变画面方案、样片扩到正式制作、整段候选交审时，执行[自我诊断](references/self-diagnosis.md)：先从原始目标定义失败条件，检查实际输出中的反例，再按原因决定改方案、演出或工程。只读完经验、修好穿帮或实现计划，不足以判整项效果通过；局部修改只诊断受影响范围，不增加审批。

[资料索引](references/library.md)列出其余按需 SOP、经验和模板；上面的画面设计必读项先按阶段触发，其余命中专题再读。

## 整期顺序与简短引导

输入已采用后按下表推进；已有适用确认直接复用。每次交审只说明“现在看什么、重点看哪里、确认后做什么”，附可打开的本次产物，一次只问当前需要的决定。内部阶段码、摘要和操作请求不作为用户的操作任务。

| 阶段 | 交给用户的内容与重点 | 确认后的下一步 |
| --- | --- | --- |
| 参考选择 | 先承接已有参考或确定由谁提供；将参考图保存在项目本地并实际打开，交本地预览与文件链接，说明借鉴范围 | 方向选定后核对角色素材，再做本片代表静态；自绘探索须有用户明确选择 |
| 静态测试 | 一幅代表画面的真实样本；看外观、信息关系与 IP | 将已确认外观和拟用运动规则写 DESIGN，直接进入制作分段 |
| 制作分段 | 配音句组、画面增量和首尾接棒；在聊天主动指出最需要检查的 1–3 项 | 一次写完文字镜头剧本；需要并行时同时说明分工 |
| 文字镜头剧本 | 完整观看过程：对象变化、镜头、阅读和衔接；直接给正文或明确可读的文件 | 用户审过这一版后才出设计图 |
| 视觉设计 | 按变化覆盖真实状态、必要的局部过程预演、运动标注与跨段衔接依据 | 总控核跨段与本批范围，再进入正式制作 |
| 制作与验收 | 首版完整过程核实适配，再精修与总装、锁画及最终音画检查；如实列未验证项 | 可编辑交付及复现说明 |

分段安排、文字剧本、设计图是三份不同的审查对象。用户回复“是／A／没问题”只对应刚展示并明确询问的版本和方面；未交文字剧本，就没有可登记的剧本确认。不能先画图、后补剧本，也不能把写在文件里但未交用户审阅当作确认。

短片或紧密依赖的内容默认在当前对话完成，不按秒数强制分支；有多个可独立制作的大段时，总控在分段交审时推荐串行或并行。选并行后仍由总控一次写剧本、统一审设计、管理公共文件与总装，分段对话只写任务书限定的片段。具体引导和回传方式见[分段协作](references/sop/03_目录与并行协作.md)。

## 必须保留的决定机制

- 全稿审查只交建议，用户选定前不擅改确认稿。正式对点绑定实际采用配音与经核对对齐材料；时长、字幕显示区间和词点是不同证据。
- 关键状态与具体对标按[规划](references/planning.md)落实；主变化、观察尺度、阅读与接棒共同排时。完整过程先成立，再精修参数，不以标签、光标微动或完成勾代替。
- 静态确认不等于动态确认。普通动作直接实现，新类型或未解风险按[测试与复用](references/style-and-motion.md#测试与复用)处理；已有适用证据复用，不增参数选档、审批或重复转低清。
- 程序化动画按[确定性与连续性](references/sop/04_验收与返修.md#程序化动画的确定性与连续性)检查本轮实际对象；状态工具通过不代表这些检查已执行。主过程实质改变后同步受影响设计，中央记录仍由总控写回。
- 图片、视频的生成和重抽由用户手动提交。Agent 只准备完整提示词、参考职责、收片检查与获准后期；工具存在或预算授权不解除边界。
- 单一总控写中央状态，分段制作可串行或多对话并行。采用、选择、进度与用户确认在 state；制作大段表为生成视图，详细待审方案单独引用。分段对话回传候选和证据，由总控登记。QA 只在唯一结构化记录区，技术检查、感知检查和用户确认分开记录。
- 候选先登记，再凭实际用户交互绑定对象、方面、摘要和允许动作；不得自行编造“用户通过”证据。没有实际观看／审听时写未验证。
- 默认同意、选择第一方案或委托执行只解决选择与制作授权，不降低效果基线。若实际输出已明确显示承诺的运镜未实现、缺少必要的观察变化、因果缺失或无用途长停，先记未通过并返修，不能用“未完成 1× 审看”掩盖已知缺陷。MG 质量证据按[状态契约](references/state-contract.md)单独核验。
- 本轮只改指定范围，保留已确认部分；文件变化按实际依赖重开受影响确认和检查。安装、登录、费用、删除、持久配置、目录结构改变和发布遵循已有授权与宿主约束。

## 工具使用

默认先用模型在当前会话中实际可用的理解与分析能力处理材料、核对内容、规划和审查；需要读取文件、检查媒体或绘制可编辑产物时，按任务使用已有工具。先完成当前能力覆盖的部分，再针对具体缺口选择辅助，不默认使用 ChatCut 或其他外部服务，也不把转写、上传或建外部项目作为语义规划的前置条件。用户已明确指定工具时承接其选择与已有授权。

模型能否直接听辨音频、查看视频或可靠定位时间，以实际输入通道和本次处理证据为准；文件路径或工具存在不代表已感知内容。能力不足时明确未验证范围，继续独立工作。配音按[模型优先与按需辅助](references/intake.md#模型优先与按需辅助)处理，不能为了“模型优先”猜测时码或声称完成未发生的审听。

使用当前已有 Node.js；路径均从 Skill 包根解析，`--project` 指向用户项目，先检查工具实际存在。不要为读文档自动安装依赖。

```text
node scripts/preflight.mjs --project <project-root>
node scripts/init-project.mjs --project <project-root>
node scripts/workflow.mjs status --project <project-root>
node scripts/workflow.mjs next --project <project-root>
```

状态修改、QA 与恢复的准确请求格式见[状态契约](references/state-contract.md)。默认正文用 `md:D01` 按稳定小节登记，不另抄一份 JSON 正文；正式批量及 S08 用 `batch-animate`，局部 pilot／animate 不代替本批正式制作授权。QA 已知失败必须由对应实际复查显式 resolves；登记后的证据文件冻结，新内容另存。现成 WAV 仅增益修订走契约中的受限证明与视觉继承路径，不凭口头等价保留旧检查。已有旧项目不会因调用入口而自动迁移。测试项目仅在 init-project 初始化时使用 `--test-only`；其他命令读取 state 中的标记，不传该开关。模拟证据不得进入真实采用。

交付时说明完成内容、实际验证、尚缺材料和未验证能力；不要把 P0 工具通过写成成片完成或首发完成。来源与改编见[许可说明](LICENSES/ATTRIBUTION.md)。
