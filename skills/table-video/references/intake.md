# S01—S02 输入与配音

先识别本次是轻量任务还是整期制作。轻量审稿、提示词或单段文字方案就地完成，不建立状态工程。正式项目的状态操作见[状态契约](state-contract.md)。新项目先核对目录与已有文件，初始化不得顺手覆盖旧项目。

## 只补影响当前工作的缺项

先从用户提供的文稿和已有配音了解任务，再按当前阶段补齐声音来源、画幅、允许画面层、已确认风格与素材。目标与受众仅在材料无法判断且会影响下一步制作时补问，不作为读稿前的必答项。画面可选全 MG、MG＋手动生成片、MG＋真实录屏、三者混合或由 Agent 推荐；这表示允许使用，不要求每段用齐、不设占比。P0 能准备这些路线的任务与状态，不能宣称已打通制作。

读取已有回答再问；一次围绕当前主题，通常不超过三个决定。用户只说“请推荐”时交可评估候选，不推断其已同意改文案、费用、生成或采用。

## 首次引导

开场优先接收文稿，已有材料就直接承接。每次围绕当前材料推进一个可检查的步骤，必要问题自然补问，不固定询问目标、受众和已有输入三件事。以下是依赖顺序，不是问卷：

1. **先接收文稿**：尚未提供时，请用户粘贴正文或指定可访问的文件路径；已有配音可一并提供。文稿不必已定稿，收到后再核对。已提供正文或路径时直接读取，不重复索要或询问是否有稿。用户只有想法、没有文稿时，说明本 Skill 不承担文稿创作，需要先准备文稿，不自行进入选题策划或写稿流程。
2. **读稿并核对声音**：先核对实际内容、文件范围及用户已明确的采用决定，按需审稿并提出建议，不因收稿自动改稿。缺配音不阻塞读稿；稿件采用明确后，再按本页声音路线引导用户使用外部 TTS 或自己录音。已有配音则直接核对，不重复询问已经明确的声音来源或无依据地要求重录。候选文件名中的“确认稿”“完整配音”不等于本轮采用；采用也不等于已经审听或对齐。
3. **画面入口**：开始依赖画面的工作前，补齐路线和画幅；涉及 IP／角色时走下节的身份入口。已明确使用 IP 却没有身份图时，可以在首次回应就引导提供，不必等配音全部完成。只做文案或配音核查时，角色缺项不阻塞独立工作。
4. **参考与静态**：身份依据明确后，按[参考入口与转场](style-and-motion.md#参考入口与转场)承接已有参考；尚无参考且来源未定时，先引导用户提供或由 Agent 查找。实际展示并选定完整画面方向后，再核对角色表现所需素材、做代表静态。静态确认后记录 DESIGN，直接进入制作分段和文字镜头剧本；运动依据经验设定，在实际片段中检查，不另设默认动态测试。访问失败不能自行改走自绘探索；用户已明确选择该分支时按其范围推进。角色外观、整场静态和实际运动的证据分别记录；只有角色图不能跳过整场参考，也不自动放行全片制作。

读过材料和已有回答后，只补问仍不清楚且会实质改变下一步制作的信息。例如，术语解释深浅取决于尚不明确的受众，或文稿有多条主线而重点不清时，再针对缺口提问。已明确的信息直接使用；不要求用户重复概括文稿、重答整套问题，或确认并未发生变化的决定。

展示材料时说明它来自本轮用户输入、用户指定沿用的项目，还是 Agent 推荐。用户明确全新开始时，不读取旧聊天或旧项目来补选择；如用户要沿用其中某个文件，只核对其明确指定的文件与范围。必要问题等待真实答复，其他已授权准备工作继续。

## IP 与角色首次入口

根据本轮需求判断是否需要角色。已经明确有或没有角色时不重问；是否使用角色仍不清楚且会影响画面时，再问这一项。名字不能确定外观，文件名、磁盘上的同名素材和作者示例都不代表本次角色采用。

| 本轮已有依据 | 当前引导 |
| --- | --- |
| 明确不使用角色 | 跳过身份图与角色说明，不强制上传 IP 图。 |
| 已提供图片或可访问路径，但尚未采用 | 实际看图，说明“这是你本轮提供的候选”，展示后询问是否用作身份外观，也允许换图；不要求重复上传，不先描述成已选角色。 |
| 有现成 IP 形象，但尚未提供可查看的图 | 请用户上传身份参考图，或给出当前可访问的文件路径／链接；访问失败时说明缺口并请其补提供，不能自行挑同名图片代替。 |
| 只有角色名字，或形象还没定 | 先问是否已有形象；确无形象时补充本次必要的外观需求，再由用户选择提供素材或准备手动生图／补画任务。角色图未收到并确认前，不编造已定外观，不代提交生成。 |
| 已有明确指向实际图片及用途的采用决定 | 回显对应图片与适用范围，核对可访问性；不重复要求上传或批准。换图或依据有冲突时只问变更点。 |

图中可观察的轮廓、比例、颜色和标志等由 Agent 整理到[角色说明](../assets/templates/角色说明.template.md)，不把整张模板当问卷交给用户。身份确认只覆盖实际展示的外观，不连带采用背景、画幅、整片画风或角色动作。后续先确定角色的叙事作用，再按[角色表演与素材充分性](style-and-motion.md#角色表演与素材充分性)检查所需姿态和部件；单张图不自动证明素材足够，也不强制预先补一套姿态。

## 进入画面规划前核对路线

可在开场确定画面形式；最迟在采用配音后、开始对应风格和分段／镜头方案前核对一次。只做文案、配音或素材核查时，不让未选画面形式阻塞独立工作。

- **未选择**：先问“这次画面用哪种组合：纯 MG、MG＋生视频、MG＋录屏、MG＋生视频＋录屏，还是先根据文案推荐？”收到选择前不直接交某一路线的分段或镜头方案。文案类型、TTS 来源、现有素材和工具可用性都不是用户的路线选择。
- **已明确选择**：简短回显选择与依据，例如“沿用你此前确认的纯 MG，接下来进入画面规划”。无需再走四选一，也不为回显增加一次批准。候选方案、Agent 推荐或未确认的旧计划不能作为依据。
- **请推荐**：结合表达任务与现有素材给推荐及理由，交用户选择；不自动把推荐写成采用，不先写详细镜头把用户带入某一路线。
- **要求回到选型／重新选择**：保留已确认文案和配音，把画面路线恢复为待选，重新呈现选项。旧分段、镜头和设计保留为历史候选，选定后再评估可复用部分；不能以“不重问”为由跳过用户要求的重测或改选。
- **改选或证据冲突**：以本次明确决定为准；有歧义时只问冲突点。改选后检查受影响分段、设计和素材；不能沿用失效的旧画面确认，也不自动重录配音。

形式表示允许的素材层，不是每段必用或固定配额。生视频仍由用户手动生成，录屏须是真实材料。画幅和风格是另外的选择，不能因确认了形式就自动采用。正式项目用现有 `choices.allowedVisualLayers` 记录：纯 MG 为 `["mg"]`，其他组合按需加入 `generated`、`screen`；`[]` 表示待选或明确退回选型，不表示全都可用。只有“请推荐”时保持待选。

完整稿想做检查时读[文案检查](sop/05_文案检查_可选.md)，使用[审稿建议模板](../assets/templates/审稿建议.template.md)。没选审稿则沿用确认稿，仍核对明显错字、音文差异；后者不授权改立场、删段或扩写。

## 三条声音路线

| 输入 | 工作 | 放行依据 |
| --- | --- | --- |
| 已有文案＋配音 | 保留原件，核对完整范围、顺序、错读、停顿 | 用户明确采用文件；影响制作的差异已解决 |
| 文案＋用户使用外部 TTS | 交[外部配音任务](../assets/templates/external-voice-task.template.md)，由用户生成，先试音后全文回传 | 真实全文核对与采用；试音通过不放行尚未生成的全文 |
| 文案＋自己录音 | 根据已采用文稿提供录制文本范围、读法、停顿、文件要求和回传位置，不另写新稿 | 收到实际音频后走已有配音核对 |

本流程默认不代生成 TTS 音频；Agent 准备读法、停顿、试音与回传说明，由用户在外部生成或自行录制。用户自备的其他来源配音按已有配音处理，不强制改用这两种方式。缺音频时可继续文稿核对和不依赖时间的准备，精确分段时长、音画对点及依赖时基的制作必须依据实际采用配音与经核对对齐材料。

P0 本身没有自动 TTS 接入。服务名称、登录状态、某个 Skill 文件存在或工具可用，都不等于本次已授权代生成配音。用户另行明确请求外部辅助时，须核对实际能力、数据发送范围与费用；不能把默认引导写成已接通的音频生成服务。

## 模型优先与按需辅助

默认由模型先理解本轮文稿、整理句子锚点、核对已有材料并推进语义规划；画面路线等必要选择已明确、当前步骤不依赖精确时间时，直接完成可审阅方案，不先要求转写、上传音频或新建外部项目。

已有配音时，先核对当前会话是否能把实际音频交给模型听辨。能直接处理时，先核对内容、顺序、错读和停顿，并记录实际处理范围；仅能读到路径、元数据或文字稿时，不能声称听过。听辨内容与可靠时间定位是两种能力：模型能听懂但不能可靠定位时，可交内容核对结果，精确对点仍待核对。模型给出的时间建议先作候选，须有与当前音频绑定、达到所需精度的核对依据，不能按字数、语速或总时长反推成事实。

只有当前步骤确实需要、且模型或已有材料无法覆盖的缺口，才选择辅助方法：先检查已授权的本地工具或已核对字幕／人工锚点能否补足；确需外部服务时再提出适用方案。ChatCut 只是可选辅助，不是默认路线或必经步骤。选择看具体缺口与实际可用能力，不因插件已暴露就优先调用。使用外部服务前按已有授权核对数据发送范围、登录与费用；已有明确授权不重问，用户指定其他方法时遵从其选择。

模型优先不改变输入依据或验收标准；无法完成的审听、时间定位分别标明未验证，只暂停依赖该缺口的部分。实际检查与记录沿用下节及[对齐记录模板](../assets/templates/alignment-record.template.md)。

## 正式时基需要实际依据

时长／流信息、转写／对齐、实际审听分别检测。FFprobe 的时长不代表听清内容，SRT 的显示区间不自动等于某词实际起音。

使用[对齐记录模板](../assets/templates/alignment-record.template.md)，至少记录音频 ID 与 SHA-256、稿件 ID 与摘要、方法、句子／词范围、时间单位、实际核对的锚点和证据。自动结果先候选，错读、停顿及关键揭示词点核对后才采用。只有人工核对材料也可继续，不强制安装 ASR。

遇到音文不一致、字幕绑定旧音频或缺少当前所需的可靠锚点，指出具体句子与缺口；受影响精确对点保持待定，继续语义规划、参考整理等独立工作。模型无法直接审听，但已有与当前音频绑定、达到本次所需精度的经核对材料时，可据此继续相应精度的对点，不重复要求转写；Agent 自身未执行的审听仍单列未验证。不得补写猜测毫秒数装成事实。

采用配音变化时分别判断内容、时长和音色／增益影响；可证明为一致正增益的现成整数 PCM WAV，按[仅增益修订](state-contract.md#现成-wav-的仅增益修订)保留原件、另存新版并以真实复查证据继承适用视觉记录，仍重查音频及最终混音。无法证明或时基变化时保守失效；依赖时基的对象关联到音频及对齐对象，更新后重新核对有效摘要。
