# 完整动作源码的选择与迁移

先按[增量核实](experience/视觉叙事与连续MG.md#设计时核实增量)明确本段对象、上下文与画面依据，再按**起因→变化→接收／结果**查找局部完整关系。完整不等于整段题材或剧情一致；提取、接收、处理、交付、比较、扩展可以分别匹配，再按本段因果组合。接触、回弹和对象连续不能自行补足内容依据；源码关系可迁移，示例题材不强套。

## 包内可运行例

新 MG 先用[共用制作起点](../assets/motion/production-core/README.md)：`scene.cjs` 定本段内容与事件，`parts.cjs` 表达部件状态，`camera.cjs`／`timing.cjs` 共同排空间观察和时间，`stage.cjs` 同次绘制并登记，`entry.jsx`／`render.cjs` 输出实际片段。复制后按内容重写机制，不沿用开发例剧情。

历史完整过程只在[源码目录](examples/05_完整过程源码.md)维护，按局部关系查真实函数再组合；可复用状态、身份、接点和反馈，不只取外层位移。包内不含依赖、原声或私人媒体，工程可运行不代表本段视觉通过。

## 四步落到本段

迁移历史实现前先按[完整过程源码复用的迁移边界](experience/视觉叙事与连续MG.md#完整过程源码复用)处理，本页只维护迁移步骤，不另存一份默认动作语言。

1. **匹配关系。** 在已有镜头剧本中写清本段的主对象、起因、实际变化、接收对象，以及例中哪些关系适用、哪些需要重写。定位结果引用具体源区间／函数；不以“没有同题材整段范例”跳过已有局部关系。未匹配部分写明缺少的关系并另设计，不逐项填无关清单。配色、字体、构图和内容服从本项目已确认输入。
2. **定位完整实现。** 一起读取实际状态、部件渲染、路径、相机和反馈。保留对象身份、前置依据与接收后果，以及下一步启动和前一步收势；不能只取曲线、换文本或截取修改后的终态。历史源码按迁移边界使用，默认新实现优先取可移植例中共用的状态入口。
3. **按新内容重排。** 根据观众当前所知，调整依据出现、部件动作、结果可见与阅读窗口；不把请求、接触或受词点约束的结果提前。再按观看任务选曲线；线根、指针、选框和跟拍绑定主体最终变换，进出与存活由完整过程决定。改内容不能只换字符串、保留相反的结局。
4. **看迁移后的完整过程。** 从本段动作时间线输出状态图和首版完整带原声预览，不按静图序号给整场统一补间。用[工程运动检查](motion-check-method.md)采样当前渲染求值函数，并与实际编码帧对照；先修过程、取景、因果和时间分配，再精修曲线。已有原版重渲或同范围预览证据直接复用。原版复现只核验环境／实现，新内容视频才验证改编；1× 观感和听校未做的仍记未验证。

设计仍按当前阶段的授权与关卡推进；这四步不增加独立审批、固定图数、镜头数或参数选档。独立静图不强制渲染视频。

## 必须保留的实现关系

| 关系 | 示例中的实现 | 改编时核对 |
| --- | --- | --- |
| 共享对象有唯一状态 | 原纸退回与镜头跟拍使用同一时刻的状态 | 动作窗口结束不等于物件消失；阶段不得重复画整套场景；首现必须与来源、实际几何和持有状态连续 |
| 路径与接点一致 | 请求进接口、结果从出口离开，之后才转向落点 | 位置、方向与遮挡共同成立；接收完成、首次接触不可混称 |
| 动作与注意力接力 | 下一对象由前一变化引出，主位移、镜头与必要反馈分开收势 | 在画内定位启动、接管与收势；下一步已经接手不等于仅有附件仍在动。避免无依据整组收口，不为填空摆动 |
| 相机服务观察 | 跟随原纸、拉开看来源与接收区、靠近比较后固定 | 核对画内承接对象、必要空间参照及合成后的屏幕运动；统一父级只证明技术关系，不能证明观看接续。空间采用与不用认[统一选择边界](experience/镜头推进与转场.md#空间镜头) |
| 历史结果独立 | 每个版本保留自己的内容和 ID | 直接跳帧与顺序求值相同，旧版不能一起变成当前版 |
| 停顿只给读字 | 有字要读时停稳；比较期间下一步已开始准备 | 阅读从完整、清晰、无遮挡时算，每秒约 5 个字；镜头可固定，画面里仍要有东西在推进；该不变的结果不能被演成成功 |

各例中的帧率、帧数、对象数量、坐标和时间预算仅描述来源过程。项目帧率、语音范围和动作预算按实际输入锁定；选择不同帧率时按秒求值并检查采样，不只修改文件名或 Composition 参数。

## 入场与跟拍实查

[第七期 v08](../assets/motion/ep07-entry-follow-v8/README.md)提供从对象来源到镜头交接的完整实现和正反回归。按本段命中的关系复用，不把整段题材、秒数或配色带入新项目。

1. **先定来源，再实现首次可见。** 在已有动作标注中写清源对象／画外来向、首次可见、过程、持有和退让／退场。复制从源物同位分出，展开从附着边生长，连线从规定端点推进；同一对象每帧一份最终状态。动作结束不等于卸载。建立状态、跨镜硬切、焦点降亮和本期 DESIGN 逐条确认的例外按[默认进出场与替换](experience/视觉叙事与连续MG.md#默认进出场与替换)区分；镜内首现、末现与同节点内容替换均检查可见过程。
2. **跟拍和主体共用最终状态。** 先求主体和父级变换，再由它及目标屏幕落点反算相机；线根、接收口也绑定该状态。调整时间预算时保留这些关联，核对屏幕实际位移、尺度及低速尾段，不仅换 easing 名称。慢的原因是时长就重排时长，是相互抵消就修关系；必要阅读保留。
3. **交付与全貌共同排时。** 需要展示去向及新增关系时，可先跟主体，再在落位过程中接入拉全景；近跟中保留必要来源／目的地，拉开后能读出关系。接点检查位置、尺度和速度，不让两段镜头各自停稳再启动；有阅读或真实依赖时允许停稳，不强制所有结尾运镜。
4. **先证明像素，再谈观感。** 用生产所用渲染器核对首次可见前、首次可见、关键中间态和完成态，并对照最终编码帧。路径进度、对象宽度、透明度或 SVG 属性非零，均不能证明真实形状已按预期显现。新渲染器、蒙版或路径揭示实现须有反例能失败的检查；本例旧 `pathLength`＋圆头虚线写法实际整条显现，真实路径前缀才渐进。按例中命令检查，不凭浏览器效果替代生产引擎。

**前后样本保留各自内容。** 从同一动态对象提取前后样本时，在对应状态仍可见时冻结：先保留改变前状态，再从完成态取出后样本；不能让两张图都跟随当前结果变化。已有独立版本素材直接复用并核对内容，不要求重演捕获。同址分出的首帧除位置、尺寸，还核对裁切、边框、底栏和阴影，原有阴影保持连续，新增分离投影按分离过程出现；检查重复绘制是否使同址边缘突然加深。真正复制出的对象有独立身份与内容，不与“同一物件每帧一份最终状态”冲突。

**接管时安排旧载体的去处。** 新对象接过注意力后，旧载体继续参与、降为次级、退出或被遮挡，应服务当前理解任务。需要看清接收与遮挡时，不能靠两套完整场景交叉淡化掩盖层级；检查过渡中与收势后有无叠影、残片或挂在画边的旧内容。保留对象可降亮退让，消失或替换须按[默认进出场与替换](experience/视觉叙事与连续MG.md#默认进出场与替换)执行。

**接收按最终阅读构图落定。** 需要稳定阅读的接收，共同安排对象落点与相机收势；落位后再次补镜须带来新的观察、揭示或交接作用，只为“再动一下”的小补位应去掉。连续跟拍和有目的的取景变化仍可使用，不能把本条解释为每次接触都必须全场停稳。

检查仍写现有 QA，区分技术状态、实际像素、1×观感及用户确认；未具备连续视频输入时，不承诺已播放或让用户反复上传，保留感知项未验证。已发现的像素缺陷先修。本例反馈只绑定本例文件和范围，不替新内容验收。

## 比较未结束时回接

[v3→v4源码](../assets/motion/relay-receive-v4/README.md)提供一次已获用户改善认可的局部修法。适用于同一载体上拆出候选、比较后回收的关系；其它题材迁移因果与接力，不照搬卡片、构图和秒数。

1. **保住比较，再让下一步进入。** 确认比较对象已达到所需可读尺度；在不遮挡、不抢焦点的条件下，接收载体先回接，候选继续可辨。需要固定精读时保留稳定取景；有真实前置事件的结果不得提前出现。
2. **接收、让位、归回交叠排时。** 下一动作在前一步收势中接过注意力，不等一组全部归位才启动下一组。各自主要位移保持利落；不能为了凑交叠拉长慢滑，或新增无意义附件运动。
3. **按最终画面绑定。** 载体移动而候选需留在原处时，用同一时刻的最终变换求位置补偿；随后再转入归回路径。复核实际屏幕位置、切线／速度、遮挡与可读范围，不靠上一帧累加，也不让相机抵消主变化。
4. **检查完整停顿及修后的去处。** 连看减速→全停→缓入，而非只量零速度区间。局部动作提前后，检查后续是否新增长停或反复小闭环；必要阅读、反问和原片接点保持。只对本次影响范围返修。

## 三项实查

在原有镜头剧本／运动标注和 QA 中完成，不另建表或审批。先看可反驳的实际证据，再作感知结论；文字标签由作者填写并不等于画面确实实现。

1. **设计增量与主对象。** 按[画面推导](planning.md#从理解目标推导画面)对照观众所知、依据和部件后果，沿[承诺核对](production.md#剧本承诺落到实际画面)定位实际时段与入口。去掉解释标签后，若只剩无新观察任务的选框或整块移动，先修过程；阅读、比较和情绪不强造内容变化。
2. **运动时段与屏幕结果。** 从实际工程核对主要变化的起止、下一步启动／接管与前一步收势，和配音句段并看。工程运动检查使用最终屏幕位置与尺寸，覆盖普通主运动、经过节点及交接，定位匀速／巡航、共同刹停、速度突变与空等；不只读世界坐标或 easing 名。适配器引用实际动作区间与求值函数，结果绑定源码／视频摘要，未声明的覆盖须保留未检查。小幅移动摊满整句、非预期相机抵消导致观看不推进，或动作完成后无用途等待，先修预算和观察关系；有意跟拍可固定主体屏幕位置，须同时核对主体世界位移、来源／接收方相对运动及取景任务，不能据单对象零速推断整场停顿，也不能仅凭“跟随”标签豁免；不得一键加速、删必要阅读或让所有对象常动。工具定位不替代对应编码帧及正常速度判断。
3. **景别与连续推进。** 选一个最相关认可完整过程，对照屏幕速度、动作关系、镜头收益和时间分配；近静止累计较多或反复短停触发对照复看与 1× 连看，每个窗口说明用途，禁止拉长已有动作压低统计。 在同一预览尺度看建立关系、近读细节与重新看全貌是否实际可辨，何时发生、为何发生。相机z数值范围大但变化来得过晚，不能证明前半段已推进；对象变小也不能自动叫近读。按适用完整范例1×对照，再连看相邻段，检查是否反复“动作—全停—动作—全停”；单次不足两秒或各自标了阅读用途不能代替整段判断。记录具体发现及不足。未正常速度观看不声称手感通过；已有帧／状态可证的缺陷先修。

[失败回归](examples/05_慢镜头与同构图回归.md)保留“14图＋11次非线性镜移仍失败”及“动作变快但逐段全停”的反例；它用于检查以上三项能否识别问题，不提供跨片硬阈值。范例回归可保留自身数值断言以发现搬运损坏，不把它们用于新内容评分。

## 能力与调用边界

包提供源码、Remotion 适配器及 v08 的 SVG／sharp 帧输出和验证器，不含这些运行依赖、浏览器或字体。使用本机已确认可用的依赖和浏览器；没有环境则报告具体缺口，继续不依赖它的设计，不自动安装、下载或改全局配置。产物写项目的独立输出目录，不写回 Skill。

渲染参数及返回日志以适配器的 `--help` 为准；指定已有 runtime、browser、入口与 Composition，静帧和视频使用不同新输出目录。渲染和轨迹测试只证明技术项，不能代替实际看片。

以下只用于 Remotion 例；v08 的 SVG／sharp 入口按其 README。从 Skill 包根执行（将占位路径替换为本次实际路径）：

```text
node scripts/render-motion-example.mjs --help
node scripts/render-motion-example.mjs --runtime <已有node_modules> --browser <已有Chrome> --entry <实际entry.jsx> --composition <实际ID> --out <项目内新静帧目录> --mode stills
node scripts/render-motion-example.mjs --runtime <已有node_modules> --browser <已有Chrome> --entry <实际entry.jsx> --composition <实际ID> --out <项目内新视频目录> --mode video
```

适配本段时将示例复制到项目源码目录，再修改实际部件与时间线；用 `--entry <本段entry.jsx> --composition <本段ID>` 调用同一适配器。入口与 Composition 显式指定；复现整份退回例可用 `--example whole-result-return`，其它案例按唯一源码目录调用；默认输出缩放 0.5，按本段需要指定 `--scale`。视频渲染关闭声音，之后按已锁定时间合入本段原声。可选 `--props <JSON文件>` 提供 `captions: [[起秒,止秒,文字], …]` 和 `heading`；这些只是本例的显示输入，完整内容适配仍须改源码。

各例的 `state-regression.json` 只锁来源状态用于搬运回归，不是新内容必须相同的目标。

## 迁移失败时怎么返修

- 运动改善但表达仍弱：检查实际对象、判断依据与后果是否可辨；线团、空栏或退回等动作不能自行证明理解增量。保留已成立的运动方法，重设计承载关系的内容，不用增加运动或装饰抵消语义不足。
- 主变化只剩卡片换词、出现消失：回到表达过程，不先调 easing。
- 有动作却像幻灯片：慢滑查屏幕速度与主动作预算；快速起停查下一步启动／接管与前一步收势、阅读范围及连续全停分布。先重排接续，不统一加速，也不以装饰余势或常驻镜头填空。
- 纸张跑出镜头、接点穿帮：修布局、路径与相机共同求值，保留已成立的动作关系。
- 代码检查通过不代表观感通过：保留技术证据；已核实观感不成立，运动结果记未通过；尚未实际观看的范围记未验证，已有缺陷仍保留未通过。不能把示例反馈继承为本段通过。
